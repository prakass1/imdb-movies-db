1. Executive Summary

Metflix ingests billions of telemetry and viewing events daily to power real-time recommendation engines and streaming analytics. Rapid feature development requires database schemas to evolve continuously. However, unannounced upstream DDL releases cause silent downstream pipeline crashes, corrupted feature tables, and hours of emergency engineering triage.

The Complete Multi-Layer Solution

Bob AI Architect operates via the Model Context Protocol (MCP) to bridge upstream database changes (movies_db) and downstream ETL pipelines (movies_etl). Upon DDL merge, Bob autonomously updates the entire data stack: Landing Zone DDL, explicit Staging CTE queries (no sloppy SELECT *), and Python Pydantic schema models in seconds.

2. Problem Statement: The Cost of Schema Drift

Workflow Stage Manual Operation Today Operational Bottleneck
1. DDL Merge Database engineer renames a column or adds a table. No automated notification to downstream ETL teams.
2. Pipeline Failure Night batch or CDC streaming job crashes on missing field. 3 to 8 hours Mean Time to Detect (MTTD).
3. Root-Cause Triage Oncall engineers manually inspect logs and commit history. 1 to 2 hours spent on manual investigation.
4. Landing Recovery Engineers manually stop jobs, drop tables, and reload CDC. High risk of data corruption from out-of-order execution.
5. Staging Remediation Engineers hand-write SQL CTEs and Pydantic models. 2 to 4 hours of manual drafting and validation.

Total Impact: 4 to 12 hours of pipeline downtime per breaking release, with over 30% of streaming data incidents traced directly to schema drift.

3. Multi-Layer System Architecture

Eliminating SELECT * & Preserving Type Safety

Bob never uses generic SELECT * fallbacks. Staging CTEs are generated with explicit column lists, preserving backward-compatible aliases (e.g. vote_count AS no_of_votes), while the corresponding Pydantic Python models in schemas/ are automatically aligned with proper type annotations.

4. Live Production Scenarios

Scenario 1: Column Rename & Drop (titles_top_100)

  • Trigger Event: Column No_of_Votes renamed to vote_count; legacy Poster_Link column dropped.
  • Audit Changelog: Created under changelogs/ capturing the schema diff and commit SHA.
  • Landing Action Issue: Published to movies_etl with explicit instructions: (1) Stop pipeline prior to Full Load (FL), (2) Drop table titles_top_100, (3) Reload CDC events.
  • Multi-Layer Draft PR: Created on branch schema-sync/titles-top-100-a3f8c12e:
    • models/landing/titles_top_100.sql (Updated DDL without poster_link, with vote_count)
    • models/staging/titles_top_100.sql (Explicit CTE selecting vote_count AS no_of_votes)
    • schemas/titles_top_100.py (Updated Pydantic model with alias mapping)

Scenario 2: New Table Onboarding (movie_reviews)

  • Trigger Event: Database team adds new movie_reviews table DDL.
  • Landing Action Issue: Published to movies_etl with CDC stream initialization and initial load setup.
  • Multi-Layer Draft PR: Created on branch schema-sync/new-table-movie-reviews-b7e2d45f:
    • models/landing/movie_reviews.sql (Landing DDL with audit columns)
    • models/staging/movie_reviews.sql (3-step explicit CTE model)
    • schemas/movie_reviews.py (Complete Pydantic BaseModel class)
